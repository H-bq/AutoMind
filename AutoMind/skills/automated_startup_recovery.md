# 技能名称
后端服务启动自愈规范

## 适用场景
- 后端服务需要启动验证。
- Agent 编排、MCP 连接、遥测中心或 API 网关启动失败。
- 本地演示环境需要判断服务是否可用。
- 启动失败需要有限诊断、有限修复和人工接管。

## 标准步骤/规范描述
- 启动后必须观察终端输出、应用日志和健康检查结果。
- 启动成功必须同时满足进程存活、关键日志正常和健康检查通过。
- 启动失败必须先归因，再决定是否重试。
- 失败归因必须覆盖端口占用、配置缺失、依赖不可用、数据库不可达、权限不足和代码异常。
- 每次修复尝试必须记录失败原因、处理动作和重试次数。
- 自动重试必须设置上限，超过上限后进入人工接管。
- 启动诊断结果必须能说明失败模块、关键错误和已尝试动作。
- 涉及数据库、MCP Server、遥测服务或外部模型服务不可用时，必须明确依赖状态。

## 特别注意事项
- 不得盲目重复启动。
- 不得为启动成功而关闭关键安全、认证或审计约束。
- 不得自动回滚用户未授权的改动。
- 不得隐藏最后一次失败的核心错误。
- 自动恢复失败后必须停止继续尝试并交还用户判断。
