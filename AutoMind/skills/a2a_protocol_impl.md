# 技能名称
A2A（Agent-to-Agent）协议实现规范

## 适用场景
- 不同行政域、业务域或网络域的 Agent 需要交换链路状态。
- 跨域路径规划需要多个 Agent 协作完成端到端最优路径。
- 本域 Agent 需要向其他域请求可用路径、SLA 能力或拥塞信息。
- 跨域通信中断时需要进入本域自治降级模式。

## 标准步骤/规范描述
- A2A 消息必须表达来源 Agent、目标 Agent、任务类型、任务状态和业务载荷。
- A2A 消息必须携带 taskId、tenantId、traceId 和时间语义。
- 链路状态交换必须覆盖链路标识、可用性、时延、丢包率、带宽占用和更新时间。
- 跨域路径规划必须区分本域决策、外域反馈和端到端合成结果。
- A2A 协议必须支持请求、响应、失败、超时和降级状态。
- A2A 通信结果必须进入 AgentTask 或审计记录，支持后续追踪。
- 跨域消息不得暴露超出协作目标所需的租户数据和内部拓扑细节。
- 跨域通信失败时，系统必须保留本域自治路径和管理员告警能力。
- A2A 协议当前阶段面向预留与模拟，必须保留未来第三方域控制器扩展点。

## 特别注意事项
- 不得把跨域 Agent 反馈视为无需校验的可信事实。
- 不得在跨域通信中传播敏感用户文本、完整租户数据或无关审计详情。
- 不得让 A2A 通信失败阻断本域基础服务。
- 不得让跨域路径规划绕过 SLA 校验和审批边界。
- 所有 A2A 消息都必须具备可追踪身份和可解释状态。
