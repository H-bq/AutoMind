# 技能名称
MCP 标准化集成规范

## 适用场景
- Intelligence Plane 需要调用模拟 SDN 控制器能力。
- Executor Agent 需要下发 QoS、流量阻断或拓扑查询任务。
- MCP Server 需要暴露 get_topo、set_qos、block_flow 等标准工具。
- MCP Client 需要统一处理能力发现、调用回执、错误码、权限和重试。

## 标准步骤/规范描述
- MCP Client 位于 Java 端，负责把 Agent 执行意图转化为标准工具调用。
- MCP Server 位于控制器侧，负责封装模拟 SDN 能力并暴露工具清单。
- MCP 消息必须包含请求标识、工具名称、参数、上下文和响应状态。
- MCP 上下文必须携带 intentId、agentTaskId、tenantId 和 traceId。
- MCP 工具能力必须登记名称、用途、输入语义、输出语义和权限边界。
- MCP 调用结果必须记录工具名、请求参数、响应码、响应体、耗时和时间戳。
- MCP 错误必须区分格式错误、参数错误、工具不存在、资源不存在、资源冲突、权限不足、超时和容量不足。
- 只有超时和资源冲突类错误允许进入有限重试。
- 权限不足、格式错误和非法请求必须立即失败并进入审计记录。
- MCP Server 必须根据租户和角色语义隔离模拟网络资源。
- 高风险 MCP 工具必须进入审批或人工确认边界。

## 特别注意事项
- 不得把 MCP 作为任意外部 API 透传通道。
- 不得让 MCP Server 执行无租户、无角色、无任务上下文的请求。
- 不得让 MCP 调用失败被静默忽略。
- 不得让可重试错误无限重试。
- 当前阶段 MCP 面向模拟 SDN 控制器，不代表真实设备已完成验证。
