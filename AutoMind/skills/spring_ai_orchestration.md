# 技能名称
Spring AI 智能体编排规范

## 适用场景
- 意图解析引擎需要调用大模型并输出结构化意图。
- Supervisor Agent 需要协调 Planner、Executor、Monitor 的任务生命周期。
- Agent 需要调用 MCP 工具、读取上下文或生成可审计决策。
- PEV 闭环需要由 AI 编排逻辑驱动计划、执行、验证和恢复。

## 标准步骤/规范描述
- 为每类 Agent 明确单一职责，避免一个 Agent 同时承担解析、规划、执行和验证。
- 意图解析输出必须包含时间、源目的地、协议、SLA 要求和置信度。
- 低置信度意图必须进入补充信息流程，不得直接进入规划或执行。
- Supervisor 负责接收已验证意图，并生成可追踪的 Agent 任务。
- Planner 负责基于拓扑、SLA 和冲突状态生成主备路径方案。
- Executor 负责把策略执行交给 MCP 工具，并记录执行结果。
- Monitor 负责读取遥测指标，对比 SLA 目标，并触发自愈流程。
- PEV 状态必须覆盖计划、执行、验证、恢复、完成和失败。
- 所有 Agent 决策必须关联 intentId、taskId、tenantId 和 traceId。
- 大模型输出必须面向结构化业务对象，避免自由文本进入核心执行链路。
- 外部工具能力必须通过明确的工具语义暴露给 Agent。
- Agent 编排必须支持超时、失败、重试、降级和人工接管状态。

## 特别注意事项
- 不得让大模型绕过权限校验、资源校验和审批边界。
- 不得让低置信度解析结果触发网络策略变更。
- 不得把自愈重规划设计成无限循环。
- 不得让 Agent 之间共享无法追踪的隐式状态。
- 所有核心 Agent 行为都必须能被审计日志解释。
